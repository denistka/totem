## 2. The ideas

**1. Define the interface from the strongest implementation.** A shim forced Claude CLI through the
chat-completions protocol; everything that made it an agent had to be discarded to fit, and the build
"succeeded" writing zero files. Not bad code — a category error. **A lowest-common-denominator
abstraction is a false-done generator.** A weaker provider must fail honestly on capability.

**2. Runtime verification is the product; the agent's success claim is untrusted input.** Every real
defect was caught by verification or live probing; none by a unit test. `build-verify` re-reads disk,
`boot-verify` proves a port, the retry ceiling bounds failure. Unit coverage is hygiene — and a rising
test count reads as progress while nothing works.

**3. Three graphs already share keys; the visual layer is a projection.** Platform = slug graph
(knowledge ↔ source ↔ runtime edges discovered at execution). Totem = plan graph (epic → `.ptl` →
`.pd` → gate). Execution = trace (events, `filesWritten`, verdicts, cost). Join keys: `slug`,
`task_id`, paths. A visualization with its own model would be a fourth graph — i.e. weeds.

**4. A task's feature footprint is computed, not declared.** Task writes files → files carry
`// SEE: feature "slug"` → `task → files → slugs` falls out with nobody maintaining it.

**5. The missing join is the commit.** The protocol prescribes `<task_id>: <description>`; there is no
`git commit` anywhere in work-control. Adding it gives manager-level rollback (`git revert`), a
decision trail as `git log`, and real ownership — no bespoke undo machinery. **Decision:** scope the
commit strictly to the task's `filesWritten`, never `git add -A`, refuse paths outside
`apps/<targetApp>/`. Patch-artifacts rejected: a second storage system is an extra entity and does not
give "own it".

**6. work-control is a harness around an agent, not an AI app.** Anyone can run a coding agent in a
terminal. Almost nobody has around it: a gate nothing bypasses, decomposition onto a board, verification
that decides "done", replay, and artifacts landing in the customer's own repo.

**7. A structural fix dissolves a bug class.** work-control is both the orchestrator *and* a resident of
`apps/` — hence `DEFAULT_TARGET_APP='work-control'`, a name-based protected guard, its own planning
stored like a customer's. That conflation is why every proposed epic dead-ended at a protected target.
Moving it out (peer of `control/`: `core/work-control/` layer + thin `work-control/` app) makes it
structurally unaddressable as a build target.

**8. Sprint artifacts are scaffolding; the slug graph is the building.** Closing a sprint must
consolidate into durable knowledge and remove what it supersedes. This day is the counter-example: ~40
generated sprints, 9 throwaway apps, three parallel summaries, an evidence folder — nothing prunes.
Metric for context health: `feature:health`, not test count.

**9. Quality over pace, with evidence.** Recorded as `APP-AGENT-PROTOCOL.md` §0.0, binding on all roles,
pointed at from `INSTANCE.ti` so it is read at load time.

## 3. Two claims I got wrong

### "Nothing runs until a human opens the gate" — FALSE
- `apply-snapshot.post.ts` also writes `wc_boards.gate` (`:11`, `:68`, `:75`), reachable from the UI
  (`useBoard.ts:177`). It never touches disk, so DB says OPEN while the `.ptl` says LOCKED.
- `getDefaultBoard` creates boards at `gate: 'OPEN'` (`repo-supabase.ts:200`, `repo-memory.ts:204`);
  `db-setup.sql:134` seeds `demo-board-1` OPEN with `task-seed-3` at `todo`.
- **On a fresh install the daemon claims and dispatches an agent with no human act.** What stopped it
  was the protected-target guard one layer below — not the gate. Filed as **S41-F14, HIGH**.

### "The work-control knowledge file is missing" — INVERTED
`feature:health` reported one broken ref all day. A workflow duly created
`core/docs/knowledge/work-control.md`. But commit `2b24b9c` had **deliberately moved that knowledge out
of core into the app layer**, so the app hands off onto a clean upstream without forking core — exactly
the portability the eventual PR depends on. The file says so in its own header.

**The real defect is the tool:** `core/cli/feature-health.js:23` scans only `core/docs/knowledge/` and
never reads the path after `at`, while the docs MCP was taught layer-awareness (`03d7752`). So it reports
a false break on a correct file — and an annotation with a genuinely *wrong* `at` path is undetectable.
That is a defect in the reference implementation and belongs in the upstream contribution.
